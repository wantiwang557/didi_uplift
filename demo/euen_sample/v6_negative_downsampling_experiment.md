# EUEN v6 全负用户下采样实验

## 1. 背景

当前 v6 EUEN 训练样本存在明显的正负不均衡。原 v6 train SQL 使用如下 outcome 过滤：

```sql
(finish_all_cnt > 0 and finish_cnt_7d > 0)
or (finish_all_cnt = 0)
```

因此训练数据呈现以下结构：

- 一个用户在训练窗口内同时存在正、负记录时，只保留该用户的正样本记录；
- 一个用户在训练窗口内全部为负时，保留该用户的全部负样本记录；
- 训练数据中的 `label == 0` 记录均来自“全负用户”。

这会使大量全负用户参与 prediction loss，可能影响模型对正样本和 treatment 差异的学习。为了验证全负用户数量对 EUEN 效果的影响，本实验保持 SQL、TFRecord、特征、模型结构和评估集不变，仅在 Python 训练数据流中对全负用户做下采样。

> 本实验针对旧 v6 EUEN prediction-loss 样本。未来 DFCL decision loss 必须使用完整、未按 outcome 筛选或下采样的 RCT 样本；不能直接沿用本实验的采样数据。

## 2. 实验数据与口径

- 模型：EUEN，4 个 treatment head 和 4 个 cost head；
- train：2026-07-16 至 2026-08-21；
- valid：2026-08-22 至 2026-08-27；
- test：2026-08-28 至 2026-09-10；
- baseline：`negative_keep_prob = 1.0`，保留全部全负用户；
- 实验组：分别保留 25%、50%、75% 的全负用户；
- 所有实验使用相同采样种子：`negative_sample_seed = 2026`；
- 只对 train 采样，`train_eval`、valid、test 均保持完整自然分布；
- 下表的 diff 均定义为：`采样版本指标 - baseline 指标`。

训练脚本：[euen_4t_negative_downsample.py](./euen_4t_negative_downsample.py)  
完整日志：[euen_4t_v6_negative_downsample.log](./run_logs/euen_4t_v6_negative_downsample.log)

## 3. 采样思路

### 3.1 用户级稳定采样

采样单位仍然是用户，而不是单条样本：

1. `label > 0` 的样本始终保留；
2. 对 `label == 0` 的样本读取 token 中的 `pid`；
3. 使用 `pid + negative_sample_seed` 计算稳定哈希；
4. 哈希结果落入保留区间时，保留该用户的全部负样本，否则全部删除。

这样可以保证同一 `pid` 的负样本不会被随机拆散。相同 seed 下，25%、50%、75%、100% 的用户集合具有嵌套关系，便于公平比较。

### 3.2 当前正负样本比例估算

四个实验对应的训练 batch 数分别为：

- 25%：556 batches；
- 50%：1085 batches；
- 75%：1615 batches；
- 100%：2147 batches。

根据 `batch_count ≈ positive_batches + keep_prob × negative_batches` 线性反推：

```text
positive_batches ≈ 25
negative_batches ≈ 2121
正样本占比 ≈ 1.16%
正样本 : 负样本 ≈ 1 : 85
```

该比例是根据 batch 数得到的近似值，不是精确行数或用户数。由于最后一个 batch 可能不满，且不同全负用户拥有的记录数可能不同，精确口径仍需在数据流中单独统计。

现有四组实验大约对应以下行级正负比：

- 25%：约 `1:21`；
- 50%：约 `1:42`；
- 75%：约 `1:64`；
- 100%：约 `1:85`。

因此，本轮即使最激进的 25% 版本也远未达到常见二分类任务中的 `1:1`。EUEN 是 uplift/outcome 回归模型，不应直接照搬二分类正负样本配比经验。

## 6. 结果结论

### 6.1 25% 下采样过于激进

25% 版本 test mean AUUC 比 baseline 下降 0.013471，mean cost AUC 下降 0.013455，且最佳 epoch 提前到 epoch 1，说明数据量下降后更容易过拟合。该比例可以排除。

### 6.2 50% 没有稳定超过 baseline

50% 的 valid mean AUUC 为四组最高，但 test mean AUUC 比 baseline 低 0.001820，valid 与 test 排序不一致，说明单次结果存在切分波动，暂不能认为 50% 更优。

### 6.3 75% 是值得复验的候选

75% 的 test mean AUUC 为 0.903773，比 baseline 提升 0.003525。收益主要来自 T1、T2、T3，其中 T1 提升 0.034616；但 T4 AUUC 下降 0.031292，不能只看 mean 指标。

同时，75% 的 mean cost AUC 比 baseline 下降 0.005109，PCOC 校准也弱于 baseline。如果线上运筹同时依赖 uplift、cost 和 treatment 4，75% 并非无条件优于全量样本。

### 6.4 当前推荐

- 不采用 25%；
- 50% 暂无明确收益；
- 将 75% 作为候选，与 100% baseline 做多 seed 复验；
- 每个 seed 内继续使用相同 seed 构造嵌套样本；
- 至少补充 3 个 seed 或 bootstrap 置信区间，确认 0.003525 的 AUUC 提升不是随机波动；
- 重点监控 T4 AUUC、四组 cost AUC、PCOC/Cal-N 和最终运筹价值，而不只看 mean AUUC。

## 7. 工程观察

下采样显著减少了送入模型的训练 batch，但没有明显缩短单 epoch 墙钟时间。25% 版本约 556 个训练 batch，100% 版本约 2147 个训练 batch，两者单 epoch 仍大致需要 4 分钟。

原因是当前实现先读取并解析完整 TFRecord，再执行 `unbatch -> pid hash filter -> batch`。因此它适合验证模型效果，但不能同比例节省 TFRecord I/O 和解析时间。如果后续目标包含训练提速，需要把过滤提前到解析前，或者预先生成采样后的训练 TFRecord；valid/test 仍应保持完整自然分布。
